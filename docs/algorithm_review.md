# 알고리즘 전면 재검토

> 수정 전 검토 기록입니다. 아래 재현 예제는 당시 엔진 기준이며, 후속 구현·검증은 [gpl-map-v2 평가](algorithm_evaluation_v2.md)에 기록합니다.

검토일: 2026-09-08. 대상은 현재 작업 트리의 `bt-diagonal-v1`, 투표 처리, 대진 선택, 표시, 재계산, 평가 코드다. 실행 코드 변경 없이 검토 결과와 후속 작업을 정리했다. 기존 구조 개편 변경은 보존했다.

## 결론

**기준별 선호를 비교로 추정하는 접근은 유지하되, 현재 온라인 갱신식과 불확실성 계산은 교체 후보로 삼는 것이 좋다.** 먼저 정적 선호에 대한 일관된 기준 모델을 만들고, 그 모델로 2-way·3-way·동률·예측·대진 선택을 연결해야 한다. 현재 수식 위에 개별 보정 계수를 추가하는 방식은 권하지 않는다.

가장 큰 문제는 동일한 투표 집합의 입력 순서에 따라 결과가 크게 달라지고, 비교로 알 수 없는 상대적 위치까지 확실해졌다고 계산한다는 점이다. 기존 합성 평균 성능이 양호하더라도 이 두 성질을 보장하지 않는다.

## 우선순위와 권고

P1은 신뢰할 수 있는 평점·확률을 위해 먼저 해결할 항목, P2는 매칭 효율과 해석 개선, P3은 정리 작업이다. 모두 현재 검토의 권고이며 적용 완료를 뜻하지 않는다.

| 우선순위 | 대상 | 판정 | 필요한 작업 |
|---|---|---|---|
| P1 | 온라인 평균 갱신 | 변경 | 동일 데이터의 순서 의존성을 줄이는 정적 재적합 기준 모델 도입 |
| P1 | 분산·상대 불확실성 | 변경 | 상대의 분산, 항목 간 공분산, 비교 그래프 연결성 반영 |
| P1 | 무승부 | 변경 | 학습과 표시가 같은 동률 우도를 사용하도록 통합 |
| P1 | 표시 확률 적분 | 수정 | 허용된 설정 범위에서도 적분 오차를 제어 |
| P1 | 3-way 학습 | 변경 | 한 순위 응답의 결합 우도 사용 또는 합성우도에 맞는 불확실성 추정 |
| P1 | 재계산 기준점 | 개선 | 전체 재학습과 기준점 이후 갱신을 구분하고 모델 교체의 범위 명시 |
| P1 | 검증 체계 | 개선 | 순서·연결성·동률·실제 매칭을 포함하는 평가 추가 |
| P2 | 기준 간 축소 | 삭제 권고 | 현재 평균만 이동시키는 옵션 제거; 독립 기준 기본 유지 |
| P2 | 대진 점수·탐색 | 개선 | 목적과 비용을 명시하고 기준 가중치·연결성·응답 가능성 평가 |
| P2 | 3-way 상대 강도 % | 삭제 권고 | 의미가 약한 정규화 지표 제거 또는 명확한 사건 확률로 교체 |
| P2 | 평가 부족·취향 변화 | 개선 | 비교 수와 정보량을 구분; 시간 효과는 별도 검증 후 도입 |
| P3 | 미사용 계산 | 삭제 | `ranking_rows()`의 소비되지 않는 `avg_sigma` 제거 |

## 1. 동일한 10승·10패가 순서에 따라 크게 달라진다

근거: [update_ratings](../ranker/rating_engine.py). 초기 두 항목 모두 `μ=0, σ²=4`, 동률 없이 A의 결과 20개를 입력했다.

| 입력 순서 | 최종 A의 μ | 최종 B의 μ | 내부 점 추정 `sigmoid(μ_A−μ_B)` |
|---|---:|---:|---:|
| 10승 → 10패 | -1.0264 | 1.0264 | 11.38% |
| 10패 → 10승 | 1.0264 | -1.0264 | 88.62% |
| 승·패 교대 | -0.0511 | 0.0511 | 47.45% |

이는 화면의 무승부 포함 승률이 아니라 학습식이 사용하는 점 추정이다. 고정된 선호와 대칭 사전분포를 가정한 정확한 BT 사후분포에서는 동일한 10승·10패의 순서는 무관하고 예측은 50%다. 온라인 근사에는 순서 오차가 있을 수 있지만 이 사례의 차이는 제품 결과에 영향을 줄 만큼 크다.

**권고:** 우선 정적 모델의 정규화된 전체 우도 재적합을 정확도 기준으로 만든다. 실용 후보는 기준별 MAP 추정과 결합 Hessian 기반 Laplace 근사다. 직전 해를 초기값으로 사용하되 같은 목적함수에 충분히 수렴하는지 확인한다. 데이터 규모별 비용을 측정한 후 매 투표 재적합 또는 주기적 재적합을 선택한다. 단순 이력 재생은 같은 갱신식을 반복하므로 이 문제를 해결하지 않는다.

최근 취향을 반영하려는 요구라면 명시적인 시간 가중이나 상태 변화 모델이 필요하다. 현재 코드에는 경과시간에 따른 변화 모형이 없으므로 위 결과를 검증된 최근 취향 반영이라고 해석할 수 없다.

## 2. 상대의 불확실성을 무시하고, 비교하지 않은 집단 사이까지 확신한다

현재 A의 갱신은 B의 평균에만 의존하고 B의 분산에는 의존하지 않는다. A의 사전분산을 4로 고정하고 두 평균이 0일 때 A가 한 번 이기는 사례를 계산했다. 정확한 BT 사후분포 기준값은 정규 실력 차이의 1차원 수치 적분으로 구했다.

| B의 사전분산 | 현재 A의 (평균, 분산) | 정확한 BT 사후 A의 (평균, 분산), 수치 근사 |
|---:|---|---|
| 0.01 | (1.0000, 2.0000) | (1.2105, 2.5347) |
| 4 | (1.0000, 2.0000) | (0.9600, 3.0783) |
| 100 | (1.0000, 2.0000) | (0.3082, 3.9050) |

더 구조적인 사례는 A–B와 C–D만 각각 1,000번 동률로 비교하는 것이다. 현재 엔진의 네 분산은 모두 바닥값 0.01에 도달하고, 한 번도 연결되지 않은 A–C의 차이 표준편차를 `sqrt(0.02)=0.1414`로 계산한다.

반면 독립 `N(0,4)` 사전에서 각 집단의 공통 위치 `(A+B)/2`, `(C+D)/2`의 분산 2는 집단 내부 비교로 줄어들 수 없다. 따라서 정확한 비교 우도에서는 A–C 차이의 표준편차가 **최소 2**다. 이 하한은 동률을 별도 모델로 바꾸더라도 우도가 실력 차이에만 의존하면 유지된다.

**권고:** 차이의 불확실성은 `V_A+V_B−2Cov(A,B)`로 다룬다. 연결되지 않은 집단의 상대 순위는 사전에 의존한다는 점을 유지하고, 집단을 연결하는 대진을 평가에 포함한다. 분산 바닥값 조정이나 단순 평균 중심화만으로는 해결되지 않는다. 온라인 방법을 유지한다면 상대 분산을 반영하는 정립된 근사도 후보로 비교하되, 현재 코드가 Weng–Lin 알고리즘과 동일하다고 취급하지 않는다. [Weng–Lin 원 논문](https://jmlr.org/papers/v12/weng11a.html)

## 3. 동률은 학습과 예측에서 다른 의미를 갖는다

근거: [평점 엔진](../ranker/rating_engine.py), [확률 어댑터](../ranker/services.py), [투표 반영](../ranker/store.py).

학습에서는 동률을 Bernoulli 결과 0.5로 처리한다. 이는 동률의 발생 확률 자체를 모델링하지 않는다. 화면에서는 기준 전체 동률 비율의 Beta 추정치를 실력이 같은 경우의 상한으로 삼고, 실력 차이에 따라 다시 감쇠한다. 선택된 대진의 주변 동률 비율을 조건부 상한으로 사용하므로 두 양이 일치하지 않는다.

예를 들어 상한 40%, 감쇠 폭 1.5라면 두 실력이 확실하고 같을 때는 40%지만, 두 평균이 같고 분산이 각각 4면 표시 동률은 14.04%다. 확실한 실력 차이가 2면 6.76%다. 불확실성 적분 자체의 오류가 아니라 입력 동률 비율의 의미가 달라지는 구조다. 3-way의 상관된 세 비교를 동률 통계에 세 건으로 더하는 것도 독립 관측 Beta 해석과 맞지 않는다.

**권고:** 2-way·3-way의 동률을 같은 모형 안에서 정의한다. 동률을 지원하는 일반화 Plackett–Luce는 후보이며, 지원하는 응답 형태와 식별 가능성을 확인해야 한다. 해당 모형은 동률과 항목 부분집합의 순위를 지원한다. [Turner 등 원 논문](https://arxiv.org/abs/1810.12068)

## 4. 고정 적분 격자는 허용된 설정에서도 오차가 크다

`predict_outcomes()`는 표준정규 좌표 간격 0.1의 고정 Simpson 격자를 쓴다. `initial_sigma=10`, `draw_bandwidth=0.1`은 모두 허용된 설정이다. 양쪽 평균 0, 분산 각각 100, 동률 상한 0.4일 때 현재 동률 적분은 **1.06385%**, 같은 휴리스틱의 해석적 적분은 **0.20000%**로 약 5.32배 다르다. 기본 분산 4와 감쇠 폭 1.5에서는 이 진단의 오차가 사실상 없었다.

실력 차이 `D~N(δ,V)`, 폭 `b`, 상한 `r`이면 현재 동률 함수의 정확한 적분은 다음과 같다.

`E[r exp(−D²/b²)] = r b / sqrt(b²+2V) × exp(−δ²/(b²+2V))`

**권고:** 모형 교체 전 이 함수를 유지한다면 동률 적분은 위 닫힌식을 사용하고, 승·패 적분은 합이 1이 되도록 일관되게 계산하면서 오차를 제어한다. 동률 함수만 바꾸고 승리 적분의 동률 감쇠 오차를 남겨서는 안 된다. 설정 극값을 포함하는 수치 정확도 검증이 필요하다.

## 5. 3-way를 세 독립 정보처럼 처리하는 정도를 줄여야 한다

현재 완전 순위는 세 쌍으로 분해되고 각 항목의 비교 수는 2 증가한다. 같은 응답 내 비교 순서가 결과를 바꾸지 않는 동시 갱신은 유지할 장점이다. 또한 UI는 최고만 선택한 상태를 제출하지 않고 최하 또는 명시적 동률을 요구한다. 나머지 두 항목을 몰래 동률로 만드는 버그는 확인되지 않았다.

문제는 세 결과가 한 효용 순위에서 나왔음에도 정보량·정밀도에 상관 보정이 없다는 점이다. 재실행한 기존 합성 평가에서도 3-way의 명목 95% 차이 구간 포함률은 **91.9~93.0%**였다. 쌍 분해 자체가 항상 잘못된 것은 아니며 추정과 효율의 조건을 따져야 한다. [Khetan–Oh 원 논문](https://jmlr.org/papers/v19/16-412.html)

**권고:** 동률 없는 완전 순위에는 PL 결합 우도를 기준으로 비교한다. `A>B>C`의 우도는 `exp(A)/(exp(A)+exp(B)+exp(C)) × exp(B)/(exp(B)+exp(C))`다. 동률 응답까지 유지하려면 동률 확장과 함께 검증한다. 쌍 분해를 유지한다면 응답 단위 상관을 반영한 불확실성 평가가 필요하다. 검증 없이 1/2 또는 1/3 보정 상수를 붙이지 않는다.

## 6. 기준 간 축소는 현재 형태를 삭제하는 편이 단순하다

`hierarchical_shrinkage()`는 투표한 기준끼리 정밀도 가중 평균 방향으로 μ만 이동시킨다. 공동 확률모형에서 유도된 학습이 아니며 이동 후 σ²는 그대로다. 건너뛴 기준에 직접 관측을 만들지 않는 점은 적절하지만, 기준 간 공유 집합이 응답 누락에 따라 달라진다.

기존 합성 평가를 재실행했을 때 반대 기준 조건의 순서 정확도는 독립 91.35%, 축소 88.48%, 명목 95% 포함률은 각각 96.16%, 66.09%였다. 비슷한 기준에서는 축소가 소폭 유리했다. 따라서 모든 공유 모델을 부정하는 결과는 아니다.

**권고:** 현행 옵션과 이에만 필요한 설정·테스트를 삭제하고 독립 기준을 유지한다. 실제 데이터가 공유의 가치를 보일 때 기준 간 상관을 학습하는 공동 모형을 따로 검토한다. 임의로 평균만 이동하는 경로는 확장하지 않는다.

## 7. 대진 선택은 목적·관측 비용과 함께 재평가해야 한다

근거: [services.py](../ranker/services.py)의 `_pair_eig`, `_select_match`, `_recent_matches`.

- **현재 점수는 정확한 EIG가 아니다.** 독립 사전의 국소 결합 Hessian 근사라면 한 쌍의 log-det 감소는 `0.5 log(1+w(V_A+V_B))`다. 현재는 두 개의 주변 로그 감소를 합쳐 초기 분산 4, 동률 실력에서 0.6931을 준다. 결합 국소식은 0.5493이다. 결합 국소식도 정확한 기대 정보량은 아니다.
- **종합 순위와 매칭 목적이 다르다.** 종합 점수는 기준 가중치를 쓰지만 대진 점수는 기준을 동일 가중치로 합산한다. 모든 기준을 균등 학습하려는 목적이면 가능하지만, 종합 순위를 빨리 확정하려는 목적에는 불일치다. 단순히 가중치를 곱하면 최적이라는 보장도 없다.
- **모르는 기준이 계속 높은 분산을 유지한다.** skip은 학습하지 않는 것이 맞다. 그러나 계속 답할 수 없는 기준의 높은 점수가 대진을 지배할 가능성이 있다. 생산 매칭으로 응답 누락 상황을 평가해야 한다.
- **최근 조합 제외는 부분쌍 반복을 막지 않는다.** A–B–C와 A–B–D는 다른 조합으로 취급된다. 사용자 피로를 줄이는 목적이라면 부분쌍 노출도 점검한다.
- **80개 초과 삼중 탐색은 후보 근사다.** 상위 10쌍에 세 번째 항목을 붙이므로 전체 최적 삼중항을 보장하지 않는다. 500개 초과는 항목 풀까지 샘플링한다. 삭제할 오류라고 단정할 근거는 없으며 최적값 대비 손실과 노출 분포를 측정해야 한다.
- **큰 이력에서 비용이 불필요하게 늘 수 있다.** `_recent_matches()`는 deep copy를 반환하는 전체 `history`를 가져와 정렬한 뒤 5개만 쓴다. 최근 요약만 조회하는 방식으로 바꿀 수 있다.

**권고:** 기본 목적은 종합 순위 오류 감소로 두고, 기준별 정밀도는 별도 평가한다. 균일 무작위·현재 매칭·새 목적 기반 매칭을 같은 응답 비용으로 비교한다. 연결성이 낮은 집단, 신규 항목, 답변 가능한 기준에 대한 탐색을 포함한다. 먼저 정확도 기준을 만든 뒤 후보 수·탐색 임계값을 조정한다.

## 8. 표시와 모델 생명주기

- **3-way 상대 강도 %는 삭제 권고.** [battle.py](../ranker/routers/battle.py)는 쌍별 승률 평균을 다시 정규화한다. 동률이 없고 순위가 확실한 A>B>C의 극한에서도 약 66.7%, 33.3%, 0%다. A의 1위 확률이 아니다. 현재 UI가 이를 승률 대신 상대 강도라고 부르는 점은 확인했다. 추가 지표의 제품 가치는 약하므로 제거하거나 정의된 1위·동률 사건 확률로 바꾼다.
- **평가 부족은 비교 건수 표식으로만 유지.** [ranking.py](../ranker/routers/ranking.py)는 기준별 5회 미만을 표시한다. 3-way 세 번이면 비교 수 6으로 해제되지만 독립 응답 여섯 번이 아니다. 비교 그래프 연결성이나 실제 순위 불확실성도 반영하지 않는다. 비교 수를 확신 또는 종료 조건으로 사용하지 않는다.
- **가중 종합 평균은 유지.** 사용자 가중치로 선호 점수를 합산하는 규칙은 단순하고 명확하다. 다만 기준별 점수 폭에는 선호 차이뿐 아니라 판단 일관성도 영향을 줄 수 있다. 가중치를 실제 효용의 정밀한 교환비로 단정하지 않고, 분산을 맞춘다는 이유로 기준별 z-score를 자동 적용하지 않는다.
- **순위 불확실성은 아직 별도다.** μ의 순위와 개별 σ만으로 순위 확정을 주장하지 않는 현재 안내는 유지한다. 사후표본 기반 순위 확률은 공동 불확실성 모델을 검증한 뒤 추가할 수 있다.
- **재계산은 전체 재학습이 아니다.** [store.py](../ranker/store.py)는 항목 추가·삭제나 기준 교체 때 과거 기록을 보관 상태로 바꾸고 현재 평점을 새 기준점으로 잡는다. 이후 재생은 그 이전 관측을 다시 적합하지 않는다. 기존 기준점 분산도 남으므로 `initial_sigma` 변경이 기존 항목의 사전을 교체하지 않는다. 현재 문서가 기준점 제한을 알리는 것은 적절하지만, 새로운 모델을 적용할 때 이 범위를 특히 명확히 해야 한다.
- **모델 교체 경로를 명시한다.** 재구성 가능한 원시 관측으로 새 버전을 처음부터 적합하거나, 재구성 불가능한 데이터는 명시적 새 시작으로 처리한다. 과거 요약 평점에 새 식만 이어 붙이고 전체가 새 모델로 재학습됐다고 표현하지 않는다. 전체 재적합 도입 시 마지막 투표 취소도 새 모델의 전체 상태와 일치해야 한다.
- **취향 변화는 후속 과제.** 현재 분산 바닥 0.01은 시간 변화 모형이 아니다. 정적 기준 모델과 시간순 예측 평가를 만든 뒤 망각·재평가 주기를 비교한다. 실제 변화가 관측되기 전에 동적 모형을 추가할 필요는 없다.

## 유지할 부분

기준별 독립 학습 기본값, skip과 동률의 분리, 3-way의 명시적 순위·동률 입력, 순수 평점 엔진, 같은 응답 내 비교 순서 불변성, 원시 투표·버전 기록, 마지막 투표 취소, 표시 위치와 동점 후보의 무작위화, 블라인드 기본값, 반올림 전 정렬 및 공동 순위는 유지한다. 학습식 교체 시에도 이 동작 계약을 보존한다.
