# gpl-map-v2 구현과 검증

2026-09-08. [사전 검토](algorithm_review.md)의 순서에 따라 평가 보강 → 평점·불확실성 교체 → 표시·재계산 통합 → 대진 선택 개선을 구현했다. 기존 구조 개편 작업은 보존했으며 배포하지 않았다.

현재 평균만 이동하는 기준 간 축소, 별도의 Beta·Gaussian 무승부 휴리스틱, 고정 Simpson 표시 적분, 3-way 상대 강도 %, 미사용 `avg_sigma`, 이전 점수 스냅샷을 사전처럼 이어 쓰는 경로는 제거했다. 블라인드 기본값, skip과 동률 분리, 명시적 3-way 입력, 원점수 정렬·공동 순위, 표시 위치 무작위화는 유지했다.

## 하나의 정적 확률모형

기준별로 독립적인 일반화 Plackett–Luce를 적합한다. 한 응답은 높은 순서대로 정렬한 항목 집합들이다. 예를 들어 `A > {B,C}`와 `{A,B,C}`는 각각 나머지 동률과 전체 동률이다. 나머지 항목 집합에서 다음 동률 집합 S를 선택하는 가중치는 다음과 같다.

`exp(mean(μ_i for i in S) + η_|S|)`, 단일 항목이면 `η_1=0`.

남아 있는 모든 비어 있지 않은 부분집합으로 정규화하고, 응답의 선택 단계 확률을 곱한다. 동률 없는 2-way는 BT, 동률 없는 다자 순위는 PL의 구조를 가진다. 현재 모형은 동률 성향도 함께 추정하므로 일반적으로 동률 없는 BT/PL과 같은 적합 결과는 아니다. 이 우도는 [PlackettLuce 저자 문서의 동률 확장](https://hturner.github.io/PlackettLuce/articles/Overview.html#extended-plackett-luce-model)을 따른다.

- 항목 사전은 독립 `N(0, initial_sigma²)`, 두 동률 로그 계수 사전은 각각 `N(0,1)`이다. 기본 `initial_sigma=2`.
- 동일 순위 응답을 횟수로 합치고, 정규 사전의 벌점과 전체 음의 로그 우도를 최소화한다. 사전 때문에 목적함수는 엄격히 볼록하다. 같은 정규화된 관측 집합은 같은 최적화 문제다.
- [SciPy L-BFGS-B](https://docs.scipy.org/doc/scipy/reference/optimize.minimize-lbfgsb.html)를 사용하고 최종 gradient의 유한성·크기를 확인한다. 수렴하지 않은 적합은 저장하지 않는다.
- 표시 `μ`는 정확한 사후평균이 아니라 MAP 위치다. `σ²`는 결합 Hessian 역행렬의 주변 분산이다. 필요한 열만 희소 선형계로 풀어 차이 공분산을 계산한다.
- 승·무·패는 같은 우도를 실력 차이와 동률 계수의 공동 정규 근사에서 적분한다. [SciPy 적응형 cubature](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.cubature.html)의 오차·수렴 판정을 사용한다. ±10 표준편차 바깥의 누락 질량은 4e-23 미만이다. 수치 오차 제어와 실사용 확률 보정은 별개의 보장이다.

최적화·적분·전체 재적합은 이벤트 루프 밖에서 실행한다. 기준을 건너뛰면 그 기준의 학습 관측과 평점은 유지하고, 대진 계획에 필요한 노출 수만 기록한다. 3-way도 기준당 **응답 한 건**이다. 평가 부족 표식은 응답한 대결이 5회 미만인 경우이며, 확신이나 종료 판정이 아니다.

위 비교는 재현 가능한 소규모 진단이다. 특히 Laplace 근사가 모든 사후분포를 정확히 표현한다는 뜻은 아니다.

## 데이터 보존과 버전 경계

순위 응답과 횟수는 정적 우도의 충분한 데이터로 따로 보존한다. 상세 이력에는 시각·선택·전후 표시 상태를 남기며, 학습에는 상세 이력의 스냅샷을 사용하지 않는다.

- 상세 이력 정리 후에도 순위 응답 횟수와 노출 수가 남아 전체 재적합할 수 있다. 개별 취소는 정리한 이력에 대해서는 불가능하다.
- 항목 추가는 기존 학습과 취소 이력을 유지한다. 삭제 항목은 화면에서 제외하되 과거 비교의 잠재 항목으로 남겨 상대의 근거를 유지한다. ID를 재사용하지 않는다.
- 기준을 제거하면 그 기준의 학습 데이터도 제거한다. 같은 키를 다시 추가해도 예전 관측이 부활하지 않는다.
- 항목 삭제·기준 구조 변경 전 상세 이력은 개별 취소를 제한한다. 보관된 상세 이력과 별개로 현재 기준에 남은 학습 관측은 전체 재계산에 포함된다.
- `initial_sigma` 변경은 보존된 모든 관측을 새 사전에서 재적합한다. 기준 가중치 변경은 개별 기준 학습을 바꾸지 않고 종합 점수와 매칭 목적에 반영된다.
- 백업 **형식 3만 지원**한다. 적합 캐시는 내보내지 않고 가져올 때 순위 응답 횟수에서 재구축한다. 취소 가능한 이력과 보존 관측 수가 맞지 않으면 거절한다.
- 이전 DB·백업의 자동 이관이나 호환 경로는 없다. 기존 파일은 수정하지 않았다. 배포 시에는 기존 원본을 별도로 보존하고 새 DB·새 랭킹을 사용해야 한다.

## 대진 목적과 탐색

현재 결합 정규 근사에서 종합 점수 차이의 순서 확률을 생각한다. 한 응답의 Fisher 정보로 예상하는 분산 감소 비율을 ρ, 현재 차이의 표준화 값을 z라 하면, 선형 Gaussian 관측 근사에서 순서 판단의 예상 Brier 위험 감소는 다음과 같다.

`Φ₂(z,z;ρ) − Φ(z)² = (1 / 2π) ∫₀^arcsin(ρ) exp(−z² / (1+sin θ)) dθ`.

이는 Gaussian 조건부 분산 분해로 계산한 설계 목적식이다. 실제 투표 이후의 정확한 사후분포나 순위 오류 감소량은 아니다. 모든 후보에 대해 같은 방식으로 계산하고 가정상 선택 수(2-way 1, 3-way 2)로 나눈다. 처음처럼 평균 차이가 0인 항목도 정보를 얻을 가치가 있으며, 이미 순서가 분명한 항목은 우선순위가 낮아진다.

기준 가중치의 제곱을 통해 종합 분산 감소를 합산한다. 기준별 응답률의 Beta(1,1) 추정치로 자주 건너뛰는 기준을 할인한다. 이는 계획용 추정이며 항목별 익숙함이나 결과에 의존하는 누락을 모델링한 것은 아니다. 최근 다섯 응답과 진행 중 대결의 부분쌍 중 반복이 가장 적은 후보를 우선한다.

최대 64개 항목을 균일 표본으로 잡고, 최대 512개 후보를 평가한다. 집중 항목은 보존하며 표시 위치는 무작위다. 표본 풀 내 순서 판단을 최적화하므로 전체 목록의 최적 후보를 보장하지 않는다. 후보 제한의 목적함수 손실도 아래 별도 측정했다.

## 합성 평가 설계

[원시 결과](algorithm_evaluation_v2.json)는 **10개 항목, 3개 기준, 가중치 3:1:1, seed 10~19, 34개 조건**이다. seed 0~9는 구현 과정의 진단에 사용했고, 최종 순서 위험 목적식은 변경하지 않은 채 별도 seed로 검증했다. 과거 v1의 12개 항목·6개 기준 평가와 수치를 직접 비교해서는 안 된다.

모델 평가에는 비슷한 기준, 반대 기준, 동률, 응답 누락, 중간 취향 반전을 포함했다. 무승부가 없으면 Gumbel/PL로, 동률 조건에서는 엔진 함수와 별도로 구현한 부분집합 선택으로 응답을 생성했다. 생성 모형이 학습 계열과 가깝다는 유리한 조건이 있다.

매칭 비교에서는 동일한 새 모델에 균일 무작위, 이전 대각 정보량 **점수** 참조, 새 생산 매칭을 적용했다. 참조 정책은 과거 온라인 엔진의 복제가 아니며, 모델과 매칭 효과를 분리하기 위한 것이다. seed별 참 실력과 잠재 응답 난수는 공유하지만 선택한 대진이 달라 실제 관측은 다르다.

모델 평가는 2-way 180회와 3-way 90회, 매칭 평가는 각각 60회와 30회다. 전체 기준에 대한 가정상 선택 예산은 같으며 실제 사람의 소요시간을 측정하지 않았다. 20회마다 고정 쌍의 사전 예측 log loss도 기록했다. 이 시간순 probe는 기준 0의 제한된 진단이다.

Brier는 승·무·패 세 클래스의 제곱 오차 합을 사용한다. 기준별 모든 쌍의 참 분포에 대한 기대 Brier/log loss를 구하며, 생성한 테스트 표를 다시 학습에 사용하지 않는다. 구간 포함률은 `V_A+V_B−2Cov(A,B)`를 사용한다. JSON의 seed 표준편차는 신뢰구간이 아니다.

## 실행 비용과 후보 제한

[벤치마크 원시 결과](algorithm_benchmark_v2.json)는 기준 하나, 무작위 완전 순위, 로컬 환경이다. 시간은 HTTP·SQLite 비용을 제외한 엔진·매칭 시간이며 RSS는 해당 벤치마크 프로세스의 누적 peak다.

| 항목 | 3-way 응답 | 전체 적합·주변 분산 계산 | 대진 선택 | 프로세스 peak RSS |
|---:|---:|---:|---:|---:|
| 50 | 300 | 0.019s | 0.087s | 128.7MiB |
| 100 | 600 | 0.014s | 0.124s | 157.7MiB |
| 500 | 2000 | 0.089s | 0.131s | 172.1MiB |
| 1000 | 3000 | 0.350s | 0.146s | 183.2MiB |

5개 별도 seed에서 모든 후보를 열거한 목적함수 최댓값과 선택 후보를 비교했다. 96개 항목에서는 전체 풀의 같은 목적식으로 다시 점수를 매겼으므로 항목 풀 표본의 영향도 포함한다.

| 항목·방식 | 전체 후보 | 선택값 / 전체 최댓값 평균 | 최솟값 |
|---|---:|---:|---:|
| 24개 · 3-way | 2024 | 96.7% | 90.3% |
| 96개 · 2-way | 4560 | 94.5% | 88.4% |

이 비율은 순위 정확도가 아니라 근사 설계 목적값이다. 후보 제한은 실제 손실을 만들며, 최대 10,000개 항목·64개 기준·64MiB 백업 한도의 동시 부하는 검증하지 않았다. 전체 재적합 비용은 관측과 항목 수에 따라 증가한다.

## 검증 및 재현

- Python 테스트 **153개 통과**: 우도·gradient·Hessian, 전체 응답 Fisher, 불확실성·수치 적분, 투표·취소·설정 변경·백업·저장 실패·누락 모형 데이터 거절을 포함한다.
- JavaScript 테스트 **10개 통과**, Ruff 통과, CSS 빌드 성공.
- 설치된 Chrome을 사용한 Playwright **16개 통과**: 데스크톱 및 모바일 다크 모드. 새 모델의 동률 통계, 상세 이력 정리 후 재계산, 비블라인드 표시와 삭제된 설정의 부재도 확인했다.
- Python 3.13 생산 Docker 빌드 성공. 로컬 임시 컨테이너를 **1 CPU·512MiB**로 제한하고 health, 2/3-way 투표, 취소, 이력 정리, 전체 재계산을 확인했다. 기존 데이터 볼륨은 사용하지 않았다. 이는 작은 목록의 실행 검증이며 최대 부하 검증은 아니다.

```bash
uv run pytest -q
uv run ruff check ranker scripts tests
npm run test:js
npm run build:css
RANKER_CHROME_PATH=/usr/bin/google-chrome npm run test:browser
uv run python -m scripts.evaluate_algorithm --seed-start 10 --seeds 10 --output docs/algorithm_evaluation_v2.json
uv run python -m scripts.benchmark_algorithm --output docs/algorithm_benchmark_v2.json
docker build -t ranker-algorithm-review:local -f docker/Dockerfile .
```

Chrome 경로는 이 환경의 값이다. Playwright 관리 브라우저가 설치된 환경에서는 `RANKER_CHROME_PATH` 없이 실행할 수 있다. 실제 사용자 데이터의 정확도·확률 보정, 실제 판단 시간, 운영 환경 부하와 배포는 수행하지 않았다.
