# 알고리즘 변경과 합성 평가

> `bt-diagonal-v1`의 과거 평가 기록입니다. 아래 재현 명령은 당시 코드 기준입니다. 현재 구현과 실행 명령은 [gpl-map-v2 평가](algorithm_evaluation_v2.md)를 참조하세요.

실행 완료: `uv run python -m scripts.evaluate_algorithm` (20개 seed, 10개 조건).
원시 수치와 seed 간 표준편차는 [algorithm_evaluation.json](algorithm_evaluation.json)에 있다.
이는 합성 진단이며 실제 사용자 정확도, 구간 보정, 3-way의 실제 시간 절약을 입증하지 않는다.

## 모델과 변경 범위

- `rating_engine.py`의 `bt-diagonal-v1`은 기존 BT 평균·분산 공식을 유지하는 순수 함수다. 2-way와 3-way가 같은 엔진을 사용하며 3-way는 원본 상태에서 세 비교를 동시에 적용한다. 교차 공분산을 추적하지 않는 대각 근사이며 정확한 결합 사후분포가 아니다.
- 기본 설정에서는 기준 간 축소를 사용하지 않는다. 명시적으로 켠 경우 기존 강도·평균 이동식을 유지하며, 건너뛴 기준은 축소에 참여하지 않는다. 기존 사용자 설정과 과거 점수가 자동으로 재학습되는 것은 아니다.
- 표시 확률은 독립 정규 근사에서 실력 차이를 적분한다. 유효한 승·무·패 확률을 각 실력 차이에서 계산하고 고정 Simpson 격자로 평균한다. 기존처럼 전달된 분산을 버리지 않는다.
- 무승부는 Beta 추정치에 실력 차이의 Gaussian 감쇠를 곱하는 표시용 휴리스틱이다. 학습의 `outcome=0.5` 우도와 같은 모델이 아니며, Beta 추정치는 감쇠 전 상한이다. 전체 실측 무승부율로 수렴한다는 보장은 없다. 기존 5~50% 제한은 제거했다.
- 정보량 매칭은 대각 근사의 점수를 유지한다. 동일 점수 후보와 표시 위치는 무작위이며, 가능하면 진행 중 조합과 최근 유효 투표 다섯 건을 피한다. 후보가 전부 최근 조합이면 반복을 허용한다. 삼중 탐색은 쌍 점수를 재사용한다.

## 평가 설계

12개 항목과 6개 기준, seed 0~19를 사용했다. `aligned_criteria`는 기준들이 비슷한 취향을 공유하고 `opposed_criteria`는 절반의 기준이 반대 방향이며 기준별 잡음을 더했다. 참 실력을 생성한 후 Gumbel 효용으로 투표를 생성한다. 이 분포의 2-way 주변 확률은 BT, 3-way 순위는 Plackett–Luce를 따른다.

대결은 균일 무작위로 선택했다. 생산 환경의 정보량 매칭 효과와 학습 모델 효과를 섞지 않기 위해서다. 무승부·모르겠음·취향 변화는 이번 평가에서 실행하지 않았다. 표시 확률 평가에서도 무승부 상한은 0이다.

기준별 모든 항목 쌍에 대해 다음을 계산했다.

- **쌍 순서 정확도**: 추정한 실력 순서가 참 순서와 같은 비율. 정확히 같은 추정치는 0.5점.
- **Brier / log loss**: 학습에 사용하지 않은 참 생성 확률에 대해 계산한 기대 점수. 작을수록 좋다. 테스트 투표를 다시 샘플링하지 않는다.
- **명목 95% 포함률**: 추정한 실력 차이 ± `1.96 × sqrt(σ²_a + σ²_b)` 안에 참 차이가 든 비율. 이는 공분산을 무시한 진단 구간이며 실제 95% 구간이라고 부르지 않는다. 식별되지 않는 절대 실력 위치 대신 쌍 차이를 평가한다.

2-way 300회가 기준이다. 3-way는 같은 생성 쌍 수(100회), 같은 가정상 판단 비용(150회), 같은 투표 수(300회)를 분리했다. 비용 가정은 기준당 2-way 한 선택, 3-way best와 worst 두 선택이며 실제 시간을 측정한 것이 아니다. 세 쌍은 상관된 결과이므로 생성 쌍 수가 같다고 정보량이 같은 것도 아니다.

| 반대 기준 포함 | 3-way, 같은 투표 수 | 300 | 94.2% | 0.1797 | 0.5351 | 92.0% |

반대 기준을 포함한 이 합성 조건에서는 기본 축소를 끈 쪽이 더 나았다. 비슷한 기준에서는 축소가 소폭 유리했으므로 축소가 항상 나쁘다는 결론은 아니다. 기본 비활성화는 사용자의 기준들이 같은 방향이라는 가정을 강요하지 않기 위한 선택이다.

3-way의 명목 95% 포함률은 약 92~93%였다. 따라서 같은 투표 수에서 순서 정확도가 높아졌다는 이유로 분산까지 보정되었다고 주장할 수 없다. 이 결과만으로 실제 판단 비용 절감도 단정할 수 없다.

원시 JSON에는 같은 학습 결과를 기존 `sigmoid(μ_a−μ_b)`로 표시한 Brier와 log loss도 함께 기록했다. 독립 2-way에서는 새 표시의 기대 점수가 소폭 개선됐지만 기존 축소 조건에서는 항상 개선되지 않았다. 분산을 반영하는 것과 실제 확률 보정이 되는 것은 별도로 확인해야 한다.

## 후속 검증과 참고

실제 투표 이력을 확보한 뒤 시간순 예측 평가, 무승부 빈도별 보정, 생산 매칭의 노출 편향, 모르는 기준의 누락, 취향 변화 및 실제 조작 시간을 확인해야 한다. 3-way의 구간 보정 개선은 그 평가에 근거해 별도 모델 버전으로 적용할 수 있다.

- [Weng–Lin: A Bayesian Approximation Method for Online Ranking](https://www.csie.ntu.edu.tw/~cjlin/papers/online_ranking/online_journal.pdf): BT 및 다자 순위 온라인 근사의 참고. 현재 엔진이 이 논문의 알고리즘과 동일하다는 의미는 아니다.
- [Khetan–Oh: Generalized Rank-Breaking](https://jmlr.org/papers/v19/16-412.html): 순위 분해에서 계산량과 추정 정확도의 관계.
- [Turner 등: Modelling rankings in R](https://arxiv.org/abs/1810.12068): 동률·부분 순위를 포함하는 Plackett–Luce 확장 참고.
