# Ranker

항목을 1대1 또는 3개씩 비교해 개인적인 선호 순위를 만드는 웹앱입니다. 이름 있는 여러 랭킹을 관리하고, 기준별 가중치와 평가 결과를 보관할 수 있습니다.

배포 주소: https://battle-ranker.fly.dev

## 사용 흐름

1. **내 랭킹**에서 이름을 정하고 항목·평가 기준을 추가합니다.
2. 대결에서 승패·동률을 선택합니다. 모르는 기준은 **건너뛰기**로 남깁니다.
3. 랭킹에서 기준별 점수를 정렬하거나 검색하고, 평가 부족·상위 5위 항목을 비교합니다.
4. 투표 내역에서 마지막 투표를 취소하거나 현재 설정으로 다시 계산할 수 있습니다.
5. JSON 내보내기로 백업합니다. 기존 랭킹에 가져올 때는 미리보기 후 확인해야 교체됩니다.

기본은 **블라인드 평가**입니다. 투표 전 순위·점수·예상 확률을 숨기며 설정에서 해제할 수 있습니다. 3개 대결에서 ‘최고만 선택’은 꼴찌를 추측하지 않습니다. 최하 또는 나머지 동률을 별도로 선택해야 합니다.

## 저장과 복구

새 랭킹은 브라우저의 개인 목록에 등록되며 직접 삭제할 때까지 보관됩니다. **내 랭킹 → 복구 코드**를 별도로 보관하면 다른 브라우저에서도 같은 목록을 열 수 있습니다. 코드를 가진 사람은 목록에 접근할 수 있습니다. 서버에는 코드의 SHA-256 해시만 저장하며, 쿠키는 HttpOnly·SameSite=Strict를 사용합니다. HTTPS에서는 `COOKIE_SECURE=true`를 설정합니다.

목록에 아직 등록하지 않은 기존 세션은 7일 비활성 시 정리됩니다. 기존 브라우저에서 ‘내 랭킹’을 열면 현재 세션을 목록에 등록합니다. 코드 분실과 서버 장애에 대비한 데이터 사본은 JSON 백업입니다.

백업 형식 3은 현재 항목·설정, 순위 응답별 횟수, 노출 수, 상세 투표 내역을 포함합니다. 랭킹 하나의 백업 한도는 **64MiB**입니다. **투표 내역 → 기록 정리**는 상세 내역만 비우고 응답별 횟수를 유지하므로 점수와 전체 재계산 능력이 보존됩니다. 서로 다른 순위 응답 자체가 한도를 차지하면 상세 내역 정리만으로 공간이 충분해지지 않을 수 있습니다.

- 형식 3만 가져올 수 있습니다. 이전 백업·이전 온라인 모델의 DB에 대한 호환·자동 이관은 제공하지 않습니다. 기존 DB 파일을 덮어쓰지 말고 새 DB와 새 랭킹에서 시작해야 합니다.
- 새 항목을 추가해도 기존 관측은 학습에 남습니다. 항목을 삭제하면 화면에서 제외하지만, 그 항목과의 과거 비교는 상대 점수 계산에 남습니다. 삭제된 항목의 ID는 재사용하지 않습니다.
- 기준을 삭제하면 해당 기준의 학습 관측도 제거합니다. 항목 삭제·기준 구조 변경 전 상세 내역은 보관하며 개별 취소를 제한합니다. 이름·가중치 변경과 항목 추가는 취소 이력을 유지합니다.
- 마지막 투표 취소는 해당 관측을 빼고 전체를 다시 적합합니다. 그 대결에 직접 참여하지 않은 항목의 점수·불확실성도 함께 복원됩니다.
- 초기 불확실성 설정을 바꾸면 보존된 모든 순위 응답을 새 사전분포로 재적합합니다. 상세 이력을 정리한 뒤에도 가능합니다.

## 알고리즘의 의미와 한계

현재 버전은 **`gpl-map-v2`**입니다. 기준별로 독립적인 일반화 Plackett–Luce 모델을 사용하며, 1대1 승패·동률과 3개 항목의 완전 순위·부분 동률·전체 동률을 하나의 우도로 학습합니다. 같은 응답 집합은 순서와 관계없이 같은 목적함수를 적합합니다. 순위 응답은 횟수로 합쳐 보존하며 매 투표마다 전체 관측에서 MAP 점수를 계산합니다.

표시 점수는 `μ × display_scale + display_center`이며 여기서 `μ`는 MAP 위치입니다. `±`는 결합 Hessian을 사용하는 Laplace 근사의 주변 표준편차입니다. 항목 간 공분산과 동률 성향의 불확실성을 함께 유지합니다. 표시 승·무·패 확률도 같은 모델의 공동 불확실성을 오차 제어 적분으로 반영합니다. 정확한 사후분포나 실사용 확률 보정을 보장하지는 않습니다.

3개 항목의 순위도 기준당 응답 한 건으로 셉니다. 평가 부족은 기준 중 하나라도 **응답한 대결이 5회 미만**이라는 표식이며 확정 순위 또는 평가 종료 조건이 아닙니다. 건너뛰기는 학습 관측을 추가하지 않습니다. 기존 기준 간 평균 축소, 별도의 무승부 감쇠 설정, 3-way 상대 강도 %는 제거했습니다.

대진은 기준 가중치·응답률·결합 공분산을 반영해 종합 순서 판단의 예상 Brier 위험 감소를 가정상 선택 비용으로 나눈 근사 점수로 고릅니다. 최근 조합의 부분쌍 반복도 가능하면 피합니다. 최대 64개 항목, 512개 후보를 표본으로 탐색하며 정확한 최적 대진을 보장하지 않습니다.

모델은 정적 선호를 가정합니다. 취향 변화·응답 누락·신규 항목·비교 집단 연결을 포함한 합성 평가와 한계는 [새 알고리즘 구현·평가](docs/algorithm_evaluation_v2.md)에 정리합니다. 실제 사용자의 정확도와 소요시간은 아직 검증하지 않았습니다.

## 개발

Python 3.13+, FastAPI, Jinja2, SQLite/aiosqlite, HTMX, Tailwind CSS를 사용합니다. 의존성은 `uv.lock`과 `package-lock.json`에 고정되어 있습니다.

```bash
uv sync --frozen --extra dev
npm ci
npm run build:css
uv run pytest
npm run test:js
```

로컬 서버는 `uv run uvicorn ranker.main:app --reload`로 시작합니다.

개발 서버와 CSS 감시:

```bash
docker compose up --build
```

http://localhost:8080 에서 실행됩니다. 개발·배포 모두 `DATABASE_PATH=/data/ranker.db`를 사용합니다. Compose의 `ranker_data` 볼륨에 DB가 저장됩니다. Docker를 사용하지 않으면 기본 경로는 `./data/ranker.db`이며 `DATABASE_PATH`로 바꿀 수 있습니다.

컨테이너에서 테스트하려면 dev 이미지의 의존성을 사용합니다. 테스트는 임시 DB를 사용합니다.

```bash
docker compose exec app python -m pytest
```

브라우저 테스트:

```bash
npx playwright install chromium
npm run build:css
npm run test:browser
```

Playwright는 임시 DB를 사용하는 로컬 서버를 자동 시작하며 데스크톱·모바일 다크모드에서 실행합니다. 이미 실행한 **별도 테스트용** Compose 서버를 검증하려면 `RANKER_E2E_BASE_URL=http://127.0.0.1:8080`을 지정합니다. 이 서버에는 테스트 랭킹이 생성됩니다. 설치된 Chrome을 사용할 때는 `RANKER_CHROME_PATH=/usr/bin/google-chrome`을 지정할 수 있습니다.

```bash
uv run ruff check .
uv run ruff format --check .
```

이미지는 루트에서 `docker build -f docker/Dockerfile -t ranker .`로 빌드합니다.

CI는 Python 테스트·Ruff·JavaScript 테스트·CSS 빌드·브라우저 테스트가 통과한 뒤 배포합니다.

## 구조와 운영 계약

[구조 검토 결과와 검증 범위](docs/structure_review.md)

| 경로 | 책임 |
|---|---|
| `ranker/main.py` | 앱 구성, 수명주기, 공통 HTTP 처리 |
| `ranker/rating_engine.py` | 저장소와 독립적인 평점 갱신·예측 |
| `ranker/services.py` | 표시 변환, 매칭, 순위 계산 |
| `ranker/store.py`, `ranker/database.py` | 세션·투표·백업, 스키마·트랜잭션·차등 저장 |
| `ranker/boards.py`, `ranker/cookies.py`, `ranker/deps.py` | 개인 목록, 쿠키 정책, 요청 의존성 |
| `ranker/routers/` | 관리·대결·랭킹·이력 HTTP 인터페이스 |
| `ranker/templates/`, `ranker/static/` | 서버 HTML, JavaScript, 자체 호스팅 라이브러리·빌드 CSS |
| `frontend/input.css` | Tailwind 원본과 템플릿 탐색 경로 |
| `docker/` | 개발·배포 Dockerfile과 컨테이너 진입 스크립트 |
| `tests/`, `tests/browser/` | Python·JavaScript 테스트, Playwright 설정·임시 서버 |
| `scripts/`, `docs/` | 알고리즘 평가 도구와 문서 |
| `.cache/`, `data/` | Git에서 제외하는 테스트 산출물과 로컬 DB |

루트에는 프로젝트 설명·라이선스, 의존성 명세·잠금 파일과 Compose·Fly·도구 설정을 둡니다. 실행 진입점은 `ranker.main:app`이며 루트 모듈 별칭은 제공하지 않습니다. 템플릿과 정적 파일은 패키지 위치를 기준으로 찾습니다.

SQLite WAL과 **단일 uvicorn 워커**를 사용합니다. 세션 변경은 락 안에서 최신 상태를 읽고, 저장은 revision을 확인합니다. 공유 커넥션 읽기도 쓰기 중간 상태와 격리하며 취소 시 rollback합니다. 항목·평점은 차등 갱신하고, 라운드 토큰만 바뀔 때 평점 전체를 다시 쓰지 않습니다.

시작 시 현재 SQLite 스키마를 생성합니다. JSON 세션 자동 이관과 이전 스키마의 열 추가는 수행하지 않습니다. 기존 DB를 사용하려면 현재 스키마(`sessions.revision` 포함)가 있어야 합니다. 데이터 파일을 자동 삭제하거나 변환하지 않습니다.

배포용 `docker/Dockerfile`은 `/data` 영속 볼륨, 단일 워커와 권한 강하를 사용합니다. `/health`는 세션 생성 없이 상태를 확인합니다. 배틀은 JavaScript가 필요하고, 일반 관리 폼에는 HTML 제출 경로가 있습니다. 스크립트와 차트 라이브러리는 자체 호스팅합니다.
